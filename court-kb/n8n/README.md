# Импорт воркфлоу в n8n НОЕ

В этом каталоге готовые JSON-файлы для импорта в n8n (Workflows → Import from File).

| Файл | Назначение | Нужен ли внешний сервер |
| --- | --- | --- |
| **`court-agent-yurist.json`** | **Прод**: живой поиск дела (слой 2) для агента «Ассистент-юриста» | **Нет** — всё внутри n8n |
| `court-agent-webhook.json` | Альтернатива: поиск по БЗ + список судов + поиск дела через отдельный Python-API | Да, Python API (Docker/VPS) |
| `scheduled-crawl.json` | Ночной обход сайтов судов (слой 1) для наполнения БЗ | Да, Python (там же, где кладёте `data/`) |
| `case-lookup-webhook.json` | Старый узкий вариант слоя 2 через Python API — не используется | Да |

## Слой 2 в проде: `court-agent-yurist.json` — без сервера, только прокси

Это воркфлоу, реально подключённое к инструменту «Поиск дела в суде» агента
«Ассистент-юриста» (webhook `court-agent-yurist`, тот же URL что и раньше:
`https://n8n-app.noya-ai.ru/webhook/court-agent-yurist`).

**Больше не нужен sweb.ru или любой другой отдельный сервер.** Раньше
предполагалось, что нужен VPS с российским IP или прокси-сервис, доступный
n8n, чтобы обойти блокировку sudrf.ru — но резидентный прокси
(`pool.proxy.market`) можно указать **прямо в ноде HTTP Request n8n**
(параметр **Proxy** в Options, поддерживает `http://user:pass@host:port`).
Вся логика — запрос формы поиска, разбор списка результатов, запрос карточки
дела, разбор секций ДЕЛО/ДВИЖЕНИЕ ДЕЛА/СТОРОНЫ — реализована в двух Code-нодах
на JavaScript внутри самого воркфлоу (порт с уже протестированной Python-
логики `scraper/case_lookup/`). Имена полей формы (`g1_case__CASE_NUMBERSS`,
`G1_PARTS__NAMESS`, `u1_case__CASE_NUMBERSS`, `U1_DEFENDANT__NAMESS`,
`delo_id` 1540005/1540006) подтверждены 20.08.2026 через
`scraper.case_lookup.discover` на всех 6 судах Воронежа и одинаковы для всех —
поэтому их можно захардкодить в ноде «Подготовить запрос», без обращения к
`courts.yaml` на лету.

### Импорт

1. n8n → Workflows → Import from File → `court-agent-yurist.json`.
2. Замените старый воркфлоу-заглушку (`Живой поиск дела ещё не подключён...`)
   этим — **id вебхука тот же** (`court-agent-yurist`), поэтому URL инструмента
   в Noya менять не нужно.
3. Нажмите **Active**.
4. Прокси уже прописан в нодах HTTP Request (`Поиск дела (через прокси)` и
   `Карточка дела (через прокси)`) — если он сменится (не резидентный/
   не sticky/протух), обновите значение поля **Proxy** в обеих нодах.
5. Протестируйте вызовом инструмента из тестового чата с реальным номером
   дела (например, найденным на сайте суда) и заведомо несуществующим —
   должны вернуться `status: found` с карточкой и `status: not_found`
   соответственно.

### Если сайт суда обновит вёрстку

Если `Поиск дела (через прокси)` начнёт возвращать `status: error` с текстом
«структура не распознана» — прогоните
`python -m scraper.case_lookup.discover --slug <suд> --delo-id 1540005 --proxy ...`
локально, сравните новые имена полей/структуру таблицы `#tablcont` и
поправьте регулярки в Code-нодах воркфлоу (они списаны 1:1 с
`scraper/case_lookup/forms.py` и `case_card.py`).

## Альтернатива с Python-API (нужен отдельный сервер)

Если хотите единый вебхук на `list_courts`/`kb_search`/`case_lookup` поверх
собранной базы знаний (слой 1), используйте `court-agent-webhook.json` —
но для него нужен постоянно работающий Python-сервис (`api/main.py`), см.
ниже. Для чистого слоя 2 (то, что подключено к юристу сейчас) это не нужно —
используйте `court-agent-yurist.json` выше.

## 1. Поднять Python-API на сервере НОЕ

На том же сервере, где крутится n8n (или на соседнем контейнере):

```bash
cd court-kb
cp .env.example .env
# отредактируйте COURT_KB_API_KEY в .env
docker compose up -d --build
curl http://127.0.0.1:8080/health
```

Должно ответить `{"status":"ok"}`.

Проверка, видит ли этот сервер сайты судов (Шаг 0 из корневого README):

```bash
curl -sS -m 15 https://sovetsky--vrn.sudrf.ru/ | head
```

Если в ответе «заблокирован по соображениям безопасности» — заполните `COURT_KB_PROXY` в `.env` российским прокси и перезапустите `docker compose up -d`.

## 2. Переменные окружения n8n

В настройках n8n НОЕ задайте:

- `COURT_KB_API_URL` — `http://127.0.0.1:8080`, если API на том же хосте; если API в Docker-сети n8n — `http://court-kb-api:8080` (имя сервиса из `docker-compose.yml`).
- `COURT_KB_API_KEY` — тот же ключ, что в `.env` API.

## 3. Импорт и активация вебхука

1. n8n → Workflows → Import from File → выберите `court-agent-webhook.json`.
2. Откройте воркфлоу, нажмите **Active**.
3. В ноде Webhook скопируйте Production URL — обычно вида `https://<домен-НОЕ>/webhook/court-agent`.
4. Этот URL подключаете агенту в НОЕ как HTTP-инструмент / webhook-действие.

Тело запроса агента (JSON):

```json
{ "action": "list_courts" }
```

```json
{ "action": "kb_search", "query": "режим работы приёмной", "court_slug": "sovetsky-vrn" }
```

```json
{
  "action": "case_lookup",
  "court_slug": "sovetsky-vrn",
  "case_number": "2-123/2026",
  "production_type": "civil_first_instance"
}
```

Если `action` не указан, воркфлоу угадывает его по полям (`case_number`/`last_name` → поиск дела, `query` → поиск по БЗ).

## 4. Ночной обход

1. Import from File → `scheduled-crawl.json`.
2. Active.
3. После первого успешного прогона в `data/corpus.jsonl` появятся страницы; `GET /corpus/export` отдаёт их для заливки в БЗ агента. Ноду заливки в БЗ НОЕ добавьте сами — эндпоинт загрузки документов зависит от конкретной сборки платформы.

## 5. Что сказать агенту в промпте

- Справочные вопросы (адрес, часы, реквизиты) → `action=kb_search`.
- «Когда заседание / статус дела №… / есть ли дела на фамилию …» → сначала `list_courts`, затем `case_lookup` с `court_slug` и номером или фамилией.
- Не вызывать `case_lookup` «на всякий случай» — это живой запрос к сайту суда, иногда с капчей.
