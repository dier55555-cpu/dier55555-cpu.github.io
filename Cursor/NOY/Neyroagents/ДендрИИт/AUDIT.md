# Аудит воркфлоу «Студия ДендрИИт - АГЕНТ»

Кабинет: **Neyroagents**. Не путать с кабинетом `NOY/dendriit/` (агенты Анна и Легион).

Дата черновика: 2026-09-07. Живые ноды с платформы в этот прогон **не сняты** — в облаке нет `NOYA_KEY_NEYROAGENTS`. Ниже: что уже ясно по официальному API Нои, чек-лист живого съёма и оценка схемы писем.

## 1. Что это за объект

Neyroagents — отдельный **аккаунт** Нои (~11 рабочих пространств). У аккаунта несколько воркфлоу. Нужный: **Студия ДендрИИт - АГЕНТ** (запрос письма, почтовый канал и т.д.).

Список пространств: `GET https://noya-ai.ru/api/workflows`.  
Чтение доски: `GET /api/workflow` + заголовок `X-Workflow-Id: <uuid>`.  
Без заголовка или с чужим uuid платформа **молча** отдаёт основное пространство.

## 2. Живой съём (блокер)

Нужен ключ кабинета Neyroagents (`nk_live_…` в секрете `NOYA_KEY_NEYROAGENTS`). После появления ключа снять в этом порядке:

1. `GET /api/key/info` — кабинет = Neyroagents, права
2. `GET /api/workflows` — найти «Студия ДендрИИт - АГЕНТ», зафиксировать uuid
3. С заголовком `X-Workflow-Id`:
   - `GET /api/workflow` — ноды и связи (каналы → агенты → действия → дожимы)
   - `GET /api/agents` и `GET /api/agents/:id` по каждому агенту на доске (промт, `config.followup`, `prompt_version`, `is_disabled`)
   - `GET /api/agents/:id/tools`, `/variables`, `/datasources`, `/triggers`, `/actions`
   - `GET /api/channels?all=true` — почта `info@studiodendriit.ru`, Авито и прочие; `is_disabled`, привязка агента
   - `GET /api/tools` — реестр действий (имена, `tool_params`, `tool_actions[].action_type`, `config.allowed_channel_ids`)
   - `GET /api/sequences` — дожимы (шаги, интервалы, `stop_on_reply`, `agent_id`)
   - `GET /api/knowledge/collections` + документы
   - `GET /api/outreach/campaigns`, `/contact-groups`, `/contacts`
   - `GET /api/dialogs?limit=20` — свежие диалоги, канал, `current_agent_id`
4. Записать факты в этот файл (имена, uuid, оценка). Промты целиком в git не класть.

## 3. Как платформа устроена (официальный API, не догадки)

База: https://noya-ai.ru/docs/api.md и OpenAPI https://noya-ai.ru/api/openapi.yaml

### Каналы и агент

Один агент может висеть на нескольких каналах. Кто отвечает на входящее (в том числе ответ на исходящее письмо) — **привязка канала к агенту на холсте**, не поле кампании.

У канала нет колонки «имя»: оно в `config.name`. Выключен = `is_disabled: true`. Чтение каналов требует права на раздел **диалогов**.

Почта: `POST /api/channels/:id/email/check`, reconnect пароля приложения. Адрес ящика сменой reconnect не меняется.

Авито тянет контекст объявления (`/api/channels/:id/avito-cache`, item-context). Это источник «чем занимается компания» для основного агента.

### Действия (tools)

`GET /api/tools` / `GET /api/agents/:id/tools`. Имя — как модель вызывает действие. `description` — когда вызывать. `tool_params` — что модель **обязана передать**. `tool_actions` — шаги платформы (`action_type` + `params`).

Частые `action_type` в живой базе: `notify`, `pause_dialog`, `add_tag`, `crm_update_field`, `http`, `crm_move_deal`, `send_message`, `set_variable`, `no_reply`. Передача другому агенту — отдельный тип шага на холсте / в действиях агента (`/api/agents/:id/actions`), не «письмо на произвольный To».

`config.allowed_channel_ids`: пусто = все каналы. `run_when_paused` — работает ли на паузе у оператора.

Кастомный `http` **может** иметь параметр адреса. Штатный outreach — нет: он шлёт контакту кампании / исходящего канала, не «email из реплики».

### «Написать первым» и почта

Это **кампании исходящих** (`/api/outreach/*`), не вызов действия из Авито-чата на чужой адрес.

- Контакт: `name`, `phone`, `username`, `email` (нужен хотя бы один способ связи). Поле `extra` в схеме пустое — описания компании штатно нет.
- Кампания: `message_text`, `channel_ids`, для почты обязателен `subject`. Канал должен уметь исходящие (Telegram-аккаунт, WhatsApp, Max, **почта**). Тестовый канал → 400.
- `message_mode`: `template` — один текст всем (так живут текущие кампании в спецификации); `ai_generated` — текст пишет агент по `ai_instruction`.
- `agent_id` у кампании **deprecated**: при создании/изменении игнорируется. Кто ведёт ответ — агент, привязанный к почтовому каналу на доске.
- Импорт: до 10 000 строк. Лимит почты по умолчанию 20 писем/час (можно 1–60).
- Запуск: `POST /api/outreach/campaigns/:id/launch`. Черновик сам не пишет.

Действие у агента «написать первым в канал диалога» (если висит на доске) бьёт в **контакт текущего диалога**. Email руководителя из текста Авито-чата — другой человек. На этот адрес штатно садится только контакт+кампания или шаг `http`.

### Дожимы и follow-up

- Нода **Дожим**: `/api/sequences` + шаги. Не путать с follow-up.
- **Follow-up** агента: `config.followup` (`enabled`, окно, `ai_instruction`, `cancel_on_resolved`, …). Это планировщик «напиши позже», не цепочка дожима.

### Передача диалога

`current_agent_id` у диалога. Передача меняет ведущего **того же** диалога (тот же канал/контакт). Авито-чат после передачи не становится письмом на другой email.

### HTTP наружу

Тип `http` в шагах действия — единственный штатный способ «агент сам отправил на To из переменной» (SMTP/почтовый API). Без этой ноды автономия сценариев 1–2 из чата невозможна.

## 4. Оценка схемы писем (замысел vs платформа)

Замысел: клиент в Авито даёт email компании / руководства; основной агент знает нишу из объявления или диалога; отдаёт это письменику; письменник через канал **«ДендрИИт - ПОЧТА info@studiodendriit.ru»** шлёт письмо «Написать первым».

| Кусок замысла | Оценка |
|---|---|
| Основной агент читает объявление Авито и диалог | Да, если канал Авито на этом воркфлоу и item-context включён |
| Собрать email + ФИО + чем занимается компания в переменные | Да, переменные агента |
| «Отдать письменнику» внутри того же Авито-чата | Только `transfer` того же диалога. Письменник тогда пишет **в Авито**, не на почту руководителя |
| Письменник на почтовом канале | Да: входящие на `info@` и ответы на кампанию, если канал привязан к нему на холсте |
| «Написать первым» на произвольный email из чата | **Нет.** Нужен контакт в исходящих + кампания, либо действие `http` |
| Список компаний от вас | Кампания / импорт CSV. Персональный текст: `ai_generated` + инструкция, либо отдельные кампании/HTTP. Шаблон = один текст на группу |
| Потом ТГ / MAX | Та же исходящая механика, другие `channel_ids` |

Итог: второй агент-письменник **нужен** (стиль, БЗ, ответы на `info@`). Связка «из Авито-чата сам вызвал Написать первым на чужой email» **не работает**. Канал почты студии — правильный отправитель для кампаний и для входящих.

## 5. Варианты реализации (этот воркфлоу)

**A. Сейчас, без доработки HTTP**  
Основной агент собирает поля и говорит, что письмо уйдёт с почты студии. Отправка: кабинет или API (контакт + кампания, тема обязательна). Письменник привязан к почтовому каналу — он продолжает после ответа. Кампанийный `agent_id` не использовать.

**B. Автономия из чата**  
Действие с шагом `http` (параметры `to`, `subject`, `body`). Составляет основной или письменник. «Написать первым» для этого сценария не нужен.

**C. Входящая почта**  
«Пусть руководитель напишет на info@». Письменник отвечает в треде. Исходящего первого письма нет.

**D. Холодные списки**  
Группа контактов + кампания на почтовый канал. Для персонализации проверить живьём `message_mode=ai_generated`.

Рекомендация: A + письменник на `info@`; B когда поток единичных писем из Авито перестанет быть ручным.

## 6. Чек-лист оценки самой доски (когда ключ будет)

- Какие агенты на воркфлоу, кто к какому каналу привязан
- Почтовый канал: имя, адрес, `is_disabled`, check
- Действия: имена, params, `action_type`, каналы; есть ли transfer / http / «написать первым»
- Дожимы: число шагов, повтор вопросов, стоп при ответе
- Follow-up основного агента: `enabled` и мини-промт
- БЗ: коллекции, дубли, search_prompt
- Переменные под email / компанию / обращение к руководителю
- Есть ли уже блок «ЗАПРОС ПИСЬМА» в инструкции
- Пустой «Новый агент» — на этой доске или нет
- Кампании исходящих: пусто или нет
- Свежие диалоги: каналы, паузы, смена агента
