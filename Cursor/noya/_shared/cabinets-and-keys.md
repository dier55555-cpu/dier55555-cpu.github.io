# Кабинеты Нои и глобальные ключи Cursor

Документ для понимания: как жить с **несколькими профилями (кабинетами)** Нои и не перепутать их.

## Карта в одной схеме

```
Платформа Ноя (noya-ai.ru)
│
├── Кабинет A  «Студия ДендрИИт»     ← уже есть (Анна)
│      └── API-ключ кабинета A
│
└── Кабинет B  «второй профиль»      ← подключаем отдельно
       └── API-ключ кабинета B       ← ДРУГОЙ ключ, не копия A

Cursor
│
├── Global Secrets / ключи окружения   ← сюда кладём значения ключей
│      NOYA_KEY_DENDRIIT = <секрет A>
│      NOYA_KEY_<SLUG>   = <секрет B>
│
└── Проектные папки (не ~/.cursor/mcp.json!)
       Cursor/noya/projects/anna/      → читает ${env:NOYA_KEY_DENDRIIT}
       Cursor/noya/projects/<slug>/    → читает ${env:NOYA_KEY_<SLUG>}
```

**Правило из методологии:** ключ не копировать между кабинетами; Ною не держать в `~/.cursor/mcp.json`.

Почему так: глобальный `mcp.json` один на все чаты Cursor. Один ключ там = агент всегда в одном кабинете и легко правит не тот профиль. Проектная папка + свой секрет = изоляция.

## Словарь

| Слово | Что это |
|-------|---------|
| **Профиль / кабинет** | Аккаунт/workspace на Ное (у ДендрИИт свой id) |
| **Доска** | Рабочая область внутри кабинета |
| **Агент** | Карточка ИИ-сотрудника (Анна, Легион…) |
| **Глобальный ключ Cursor** | Секрет в Cursor (Secrets / env), доступный агенту как переменная окружения |
| **Ключ кабинета Нои** | API/MCP-ключ, который выдаёт Ноя для доступа к **этому** кабинету |

Глобальный ключ Cursor — это **хранилище**. Ключ кабинета Нои — это **значение**, которое туда кладут.

## Как подключить второй профиль (чеклист)

### 1. В Ное

1. Открыть нужный кабинет (второй профиль).
2. Выпустить **свой** API/MCP-ключ этого кабинета (не брать ключ ДендрИИт).
3. Запомнить: имя кабинета, id кабинета, id доски (если уже есть).

### 2. В Cursor — глобальный секрет

1. Открыть [Cloud Agents / Secrets](https://cursor.com/dashboard/cloud-agents) или Settings → Secrets.
2. Добавить переменную с **уникальным именем**:
   - для Анны/ДендрИИт: `NOYA_KEY_DENDRIIT`
   - для нового: `NOYA_KEY_<SLUG>` (латиница, без пробелов; slug = имя папки проекта)
3. Тип: **Runtime Secret** (чтобы значение не утекало в чат/коммиты).
4. Значение = ключ из кабинета Нои. В git и в чат ключ не писать.

### 3. В репозитории — папка проекта

```text
Cursor/noya/projects/<slug>/
  README.md                 # имя кабинета, id, какие агенты можно трогать
  .cursor/
    mcp.json                # MCP Нои + ${env:NOYA_KEY_<SLUG>}  (без литерала ключа)
    rules/
      noya-cabinets.mdc     # кабинет/доска/агенты ЭТОЙ папки
```

Шаблон: `Cursor/noya/projects/_template/`.

Скопировать шаблон → переименовать `<slug>` → подставить имя секрета и id из Нои.

### 4. Проверка перед работой

В чате Cursor в **этой** папке проекта:

1. Вызвать MCP `whoami` (или аналог из `instruction_guide`).
2. Убедиться: имя кабинета = то, что в `noya-cabinets.mdc`.
3. Не совпало → **стоп**. Не править агентов. Проверить секрет и `mcp.json`.
4. Совпало → `list_agents` → назвать вслух кабинет → доска → агент (имя + id) → работать.

## Как потом работать каждый день

| Задача | Куда открыть | Какой секрет должен быть активен |
|--------|--------------|----------------------------------|
| Править Анну | `Cursor/noya/projects/anna/` | `NOYA_KEY_DENDRIIT` |
| Править второй профиль | `Cursor/noya/projects/<slug>/` | `NOYA_KEY_<SLUG>` |
| Общая методология | `Cursor/noya/_shared/` | ключ не нужен (только чтение правил) |

Перед любой правкой агента на Ное:

1. `instruction_guide`
2. `whoami`
3. Сверить с `.cursor/rules/noya-cabinets.mdc` этой папки
4. Дальше по методологии §0 (`Методология_НОЯ.txt`)

## Что нельзя

- Один и тот же ключ Нои в двух секретах «для удобства»
- Ноя в `~/.cursor/mcp.json` (глобальный MCP на все проекты)
- Ключ в git, в README, в `noya-cabinets.mdc`, в чате
- Править агентов, пока `whoami` не совпал с правилом папки
- Класть второй кабинет в папку Анны «чтобы не плодить папки»

## Второй профиль — что прислать агенту

Чтобы агент донастроил папку под новый кабинет, достаточно:

1. **Slug** папки (латиница), например `potolki` или `client2`
2. **Имя кабинета** как в Ное
3. **Id кабинета** (и доски, если есть)
4. Подтверждение: секрет `NOYA_KEY_<SLUG>` уже добавлен в Cursor Secrets (значение в чат не слать)

После этого агент создаёт папку из `_template/`, пишет `noya-cabinets.mdc` и `mcp.json` с `${env:…}` — без самого ключа.
