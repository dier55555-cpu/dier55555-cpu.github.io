# Кабинеты и проекты + глобальные ключи Cursor

## Главное правило (не путать)

| Уровень | Что это | Пример |
|---------|---------|--------|
| **Кабинет** | Профиль на Ное; один API/MCP-ключ | Студия ДендрИИт |
| **Проект** | Работа внутри кабинета; в кабинете их **несколько** | Анна, Битрикс-Юрист |
| **Агент** | Карточка ИИ на доске кабинета | Анна, Легион |

**Кабинет ≠ проект.** Анна — не кабинет, а один из проектов кабинета ДендрИИт. Битрикс-Юрист — другой проект **того же** кабинета.

Ключ Cursor (`NOYA_KEY_…`) — **на кабинет**, общий для всех его проектов.

## Локальный корень

Всё лежит в:

```text
/Users/user/Projects/
```

В этом репозитории то же дерево зеркалится под `Cursor/` (для cloud-агентов и правил).

## Схема

```text
/Users/user/Projects/                    (= Cursor/ в этом репо)
│
├── _shared/                             методология Нои (все кабинеты)
├── _cabinet-template/                   шаблон нового кабинета
│
├── dendriit/                            КАБИНЕТ «Студия ДендрИИт»
│   ├── .cursor/
│   │   ├── mcp.json                     → ${env:NOYA_KEY_DENDRIIT}
│   │   └── rules/noya-cabinets.mdc      id кабинета + список проектов
│   ├── anna/                            ПРОЕКТ
│   └── bitrix-yurist/                   ПРОЕКТ
│
└── <cabinet-slug>/                      другой КАБИНЕТ (второй профиль Нои)
    ├── .cursor/mcp.json                 → ${env:NOYA_KEY_<CABINET>}
    ├── project-a/
    └── project-b/
```

```text
Ноя                          Cursor Secrets              Папка
─────────────────────        ──────────────────          ─────────────────
Кабинет ДендрИИт  ──ключ──►  NOYA_KEY_DENDRIIT  ──────►  Projects/dendriit/
Кабинет B         ──ключ──►  NOYA_KEY_<SLUG>    ──────►  Projects/<slug>/
```

**Правило методологии:** ключ не копировать между кабинетами; Ною не держать в `~/.cursor/mcp.json`.

## Как работать каждый день

1. Открыть в Cursor папку **кабинета**: `/Users/user/Projects/dendriit` (не только `anna/`).
2. `instruction_guide` → `whoami` → сверить с `dendriit/.cursor/rules/noya-cabinets.mdc`.
3. Работать в нужном **проекте** внутри кабинета (`anna/` или `bitrix-yurist/`).
4. Назвать вслух: кабинет → проект → агент (имя + id).

| Задача | Открыть | Секрет |
|--------|---------|--------|
| Анна | `…/Projects/dendriit/` (+ файлы в `anna/`) | `NOYA_KEY_DENDRIIT` |
| Битрикс-Юрист | `…/Projects/dendriit/` (+ файлы в `bitrix-yurist/`) | `NOYA_KEY_DENDRIIT` (тот же) |
| Другой кабинет Нои | `…/Projects/<cabinet>/` | `NOYA_KEY_<CABINET>` |

## Подключить второй кабинет (профиль Нои)

Не новая папка рядом с Анной — **новый кабинет** рядом с `dendriit/`.

1. В Ное: открыть второй кабинет → выпустить **свой** ключ.
2. В Cursor Secrets: `NOYA_KEY_<CABINET>` (Runtime Secret). Значение в чат/git не писать.
3. Скопировать `_cabinet-template/` → `/Users/user/Projects/<cabinet>/`.
4. Заполнить `.cursor/rules/noya-cabinets.mdc` и `mcp.json` с `${env:NOYA_KEY_<CABINET>}`.
5. Внутри создать папки проектов. `whoami` перед работой.

Что прислать агенту (без ключа): slug кабинета, имя + id, список проектов, подтверждение что секрет уже в Secrets.

## Что нельзя

- Считать Анну «кабинетом»
- Класть Битрикс-Юрист вне ДендрИИт «потому что другой стек»
- Один ключ Нои на два кабинета
- Ноя в `~/.cursor/mcp.json`
- Ключ в git / README / чат
- Править агентов, пока `whoami` не совпал с правилом **кабинета**
