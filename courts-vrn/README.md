# Районные суды Воронежа → агент Нои

Шесть сайтов — **одна** ГАС «Правосудие», разные хосты. Агенту Нои не нужно шесть парсеров.

## Решение

| Слой | Зачем | Как |
| --- | --- | --- |
| **БЗ в Ное** | 90% вопросов: какой суд, адрес, телефон, режим, куда кликать | Файлы `kb/knowledge-base.md` + `data/courts.json` |
| **Действие HTTP** | Агент подтягивает карточки без копипаста | GET JSON с GitHub Pages |
| **Не парсить sudrf из облака** | BigIP, обрыв TLS, капча на поиске дел | Прямой curl с датацентра падает |
| **Этап 2 (по желанию)** | Живой статус дела по номеру/ФИО | Отдельный сервер в РФ + Playwright/сессия `sud_delo`, действие-webhook в Ное |

Агента «Легион» не меняем. Это вторая доска / второй агент в кабинете «Студия ДендрИИт».

## Как завести в Ное

1. Новая доска, например «Суды Воронежа».
2. Новый агент: имя «Суды Воронежа — справочник», цель — квалификация/справка (не продажа Легиона).
3. В БЗ — содержимое `kb/knowledge-base.md` и при необходимости JSON.
4. Промпт — `kb/agent-prompt.md`.
5. Действие: GET `https://dier55555-cpu.github.io/courts-vrn/data/courts.json` (после мержа в `main`).
6. Если `whoami` пишет «агентов_доступно: 1» — платформа может отказать; смотреть текст ответа API.

В этом репозитории нет MCP Нои: создать доску из этого чата нельзя. Готовые тексты вставляются в кабинете или в чате, где подключён MCP Нои.

## Этап 2: живой парсер

Нужен только если агент должен **сам** находить дело, а не отдавать ссылку.

1. VPS / домашний сервер с российским исходящим IP.
2. Один адаптер на шаблон ГАС: cookie → форма `sud_delo` → JSON (номер, стороны, судья, дата, результат из открытой публикации).
3. Webhook действия Нои: `court_id` + `case_number` или ФИО.
4. Не складывать в БЗ персональные карточки заседаний.

Пока этапа 2 нет, честный ответ агента: «Откройте поиск на сайте суда» + URL.
