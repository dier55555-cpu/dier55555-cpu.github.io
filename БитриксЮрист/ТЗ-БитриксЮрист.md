# Техническое задание  
## Система «БитриксЮрист» — мониторинг судебных дел в Битрикс24

**Версия:** 1.0  
**Дата:** 26.08.2026  
**Назначение документа:** описание продукта, порядок внедрения, требования к инфраструктуре и ориентировочные расходы на 12 месяцев.

---

## 1. Цель и результат

### 1.1. Цель
Автоматически раз в сутки проверять актуальный статус судебных дел на официальных сайтах судов Российской Федерации и фиксировать изменения в карточках сделок Битрикс24.

### 1.2. Результат для пользователя
Сотрудник открывает сделку и видит в ленте комментарий вида:

```text
[БитриксЮрист] Обновление дела произведено
Проверено: 26.08.2026 06:14 (МСК)
Номер: 2-1248/2026
Статус на сайте: …
Что изменилось: …
Карточка суда: https://…
```

Дополнительно обновляются служебные поля сделки (статус, дата проверки, сайт суда и др.).

### 1.3. Что система делает ежедневно
1. Читает сделки выбранной воронки Битрикс24, у которых заполнен номер дела.  
2. По региону / городу / району / названию суда определяет официальный сайт суда из справочника (~10 000 судов и мировых участков РФ).  
3. Запрашивает карточку дела на сайте суда (районные/городские суды и мировые судьи).  
4. Сравнивает с предыдущим снимком.  
5. При изменении — обновляет поля сделки и пишет комментарий в ленту с датой и временем (часовой пояс Europe/Moscow).

### 1.4. Что система не делает (в текущей версии)
- не ведёт диалог с клиентом в мессенджерах;  
- не заменяет юриста и не даёт правовых заключений;  
- не публикует API в интернет (работает только внутри сервера клиента).

Уведомления во внешние каналы (WhatsApp, Telegram, SMS) могут быть добавлены отдельным этапом.

## 2. Состав решения

| Компонент | Назначение |
| --- | --- |
| Модуль «Парсер дел» | Поиск суда и загрузка карточки дела с сайтов судов |
| Справочник судов РФ | База сайтов судов и мировых участков |
| Модуль «Битрикс-агент» | Обход сделок, запись полей и комментариев |
| Планировщик | Ежедневный запуск (по умолчанию 06:00 МСК) |
| Интеграция Битрикс24 | Входящий вебхук REST CRM |

Все компоненты устанавливаются на **один выделенный VPS в Российской Федерации**.

```text
Битрикс24 (облако клиента)
        ▲
        │ REST (входящий вебхук)
        │
VPS клиента (РФ)
  ├── Парсер дел          (localhost:8081)
  ├── Справочник судов
  └── Битрикс-агент + таймер 06:00 МСК
        │
        ├── RU-прокси (внешний сервис)
        └── сервис распознавания капчи (для мировых судей)
```

## 3. Требования к Битрикс24 клиента

### 3.1. Портал
Облачный или коробочный Битрикс24 с доступом к CRM и REST API.

### 3.2. Воронка сделок
Согласовывается отдельная воронка (или существующая), сделки которой подлежат мониторингу. Указываются:
- идентификатор воронки (`CATEGORY_ID`);  
- список стадий (`STAGE_ID`), которые нужно обходить.

### 3.3. Поля сделки
В сделке должны быть (или создаются) пользовательские поля:

| Назначение | Пример кода поля | Кто заполняет |
| --- | --- | --- |
| Номер дела | `UF_CRM_CASE_NUMBER` | сотрудник |
| Название суда | `UF_CRM_COURT_NAME` | сотрудник |
| Регион | `UF_CRM_REGION` | сотрудник |
| Город | `UF_CRM_CITY` | сотрудник |
| Район | `UF_CRM_DISTRICT` | сотрудник (желательно) |
| Сайт суда | `UF_CRM_COURT_WEBSITE` | система |
| Последний статус | `UF_CRM_LAST_STATUS` | система |
| Дата/время проверки | `UF_CRM_LAST_CHECK_AT` | система |
| Служебный хэш снимка | `UF_CRM_SNAPSHOT_HASH` | система |

Коды полей могут отличаться — они прописываются в конфигурации при внедрении.

### 3.4. Входящий вебхук
Создаётся входящий вебхук пользователя с правом **CRM**.  
Формат: `https://<портал>.bitrix24.ru/rest/<ID>/<код>/`  
Секрет вебхука хранится только на сервере клиента, в открытый доступ не передаётся.

### 3.5. Правила заполнения сделки
Для корректной работы в сделке обязательно:
- номер дела;  
- регион и город;  
- название суда (для мировых — с номером участка и районом, например: «судебный участок № 1, Советский»).

## 4. Требования к инфраструктуре

### 4.1. VPS (обязательно)

| Параметр | Минимум для продакшена |
| --- | --- |
| Расположение | дата-центр **в РФ** |
| ОС | Ubuntu 22.04 LTS (или совместимая) |
| CPU | 2 vCPU |
| RAM | 2 ГБ (рекомендуется) |
| Диск | от 20 ГБ SSD/NVMe |
| Сеть | выделенный IPv4 |
| Доступ | SSH по ключу, права root |

Публичный домен и SSL для системы **не требуются**: сервисы слушают только `127.0.0.1`.

### 4.2. Прокси с российскими IP (обязательно)
Сайты судов ограничивают автоматизированные запросы. Для стабильной работы нужен пул HTTP(S)-прокси с IP в РФ (резидентские или ISP).

Рекомендуемые параметры на старте:
- геолокация: Россия;  
- 5–20 sticky-портов;  
- пакет трафика от 10 ГБ.

### 4.3. Сервис распознавания капчи (обязательно для мировых судей)
На сайтах мировых судей почти всегда показывается графическая капча. Используется API-сервис распознавания (RuCaptcha / 2captcha или аналог).

### 4.4. Справочник судов
Поставляется в составе решения (JSON на сервере, ~10 000 записей).  
Обновление справочника выполняется по регламенту сопровождения (выгрузка из актуальных таблиц судов РФ).

## 5. Порядок внедрения

### Этап 1. Подготовка на стороне клиента
1. Подтвердить воронку и стадии.  
2. Создать/проверить поля сделки.  
3. Создать входящий вебхук CRM.  
4. Подготовить 2–3 тестовые сделки с реальными номерами дел.  
5. Передать исполнителю: URL вебхука, `CATEGORY_ID`, список стадий, коды UF-полей.

### Этап 2. Инфраструктура
1. Аренда VPS в РФ.  
2. Регистрация и оплата прокси РФ.  
3. Регистрация и пополнение сервиса капчи.  
4. Выдача SSH-доступа исполнителю (отдельный ключ).

### Этап 3. Установка
1. Развёртывание парсера дел и справочника судов.  
2. Развёртывание битрикс-агента и таймера.  
3. Запись конфигурации (вебхук, поля, прокси, ключ капчи).  
4. Включение автозапуска служб.

### Этап 4. Приёмка
Проверяется:
1. Служба парсера отвечает на проверку работоспособности.  
2. Суд находится по региону/названию.  
3. Карточка дела читается с сайта районного суда.  
4. Карточка дела читается с сайта мирового судьи (с капчей).  
5. Тестовый прогон в режиме «без записи» проходит без ошибок.  
6. Боевой прогон на тестовой сделке: поля обновлены, в ленте есть комментарий с датой МСК.  
7. Таймер показывает следующий запуск (06:00 МСК по умолчанию).

### Этап 5. Передача в эксплуатацию
Клиенту передаются:
- установленное ПО на его VPS;  
- инструкция по логам и ручному запуску;  
- доступы к кабинетам VPS / прокси / капчи (если оформлены на клиента);  
- регламент обновления справочника судов.

Секреты (вебхук, ключи API) в открытой переписке и в git не хранятся.

## 6. Регламент работы

| Параметр | Значение по умолчанию |
| --- | --- |
| Расписание | ежедневно в 06:00 (МСК) |
| Комментарий в ленту | при изменении статуса дела |
| Поле «дата проверки» | обновляется при каждой успешной проверке |
| Пауза между сделками | ~5 секунд (снижение нагрузки на сайты судов) |
| Повтор при сбое сайта суда | до 2 попыток в рамках прогона |

Если сайт суда временно недоступен, в сделку **не** пишется формулировка «Обновление дела произведено». Фиксируется служебный статус ошибки для контроля.

## 8. Сопровождение и обновления

В рамках долгосрочной эксплуатации рекомендуется:

1. Еженедельно контролировать балансы прокси и капчи.  
2. Ежемесячно просматривать логи неуспешных проверок.  
3. По мере изменений на сайтах судов — устанавливать обновления парсера (патчи поставляет исполнитель).  
4. При изменении структуры судов РФ — обновлять справочник.  
5. Хранить резервную копию конфигурации `.env` и каталогов `/opt/bitrix-delo`, `/opt/bitrix-yurist` (без публикации секретов).

Абонентское сопровождение (реакция на сбои, обновления, консультации) оформляется отдельным соглашением.

## 9. Безопасность

1. API парсера доступен только с localhost сервера.  
2. Вебхук Битрикс24 и ключи сервисов хранятся в файлах окружения на VPS с ограниченными правами.  
3. Секреты не передаются в открытых чатах и не включаются в репозиторий.  
4. SSH-доступ — по персональным ключам; парольный root по возможности отключается.  
5. Резервное копирование конфигурации — на стороне клиента или по договору сопровождения.

## 10. Критерии приёмки

Система считается принятой в промышленную эксплуатацию, если:

- [ ] службы установлены и запускаются автоматически после перезагрузки VPS;  
- [ ] ежедневный таймер активен;  
- [ ] успешно определяется сайт суда по полям сделки;  
- [ ] успешно читается дело районного суда;  
- [ ] успешно читается дело мирового судьи;  
- [ ] на тестовой сделке появляется корректный комментарий в ленте;  
- [ ] поля статуса и даты проверки заполняются;  
- [ ] переданы доступы к инфраструктуре и краткая инструкция эксплуатации.
